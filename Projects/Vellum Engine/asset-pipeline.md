How content gets from files on disk into the renderer: handles, loading off the main thread, GPU uploads, the special assets NPR needs (ramps, hatch maps, paper, smoothed normals) and reloading while it runs. Part of [Engine Overview](page:3vibzoegdx).

---

## 1\. What an asset pipeline does

| Stage | What happens | When |
| --- | --- | --- |
| **Author** | Blender, Krita export meshes, ramps, hatch strokes, paper scans | offline |
| **Import / cook** | Build what NPR needs from a mesh: smoothed normals, edge adjacency, crease flags; compress textures | offline or first load |
| **Load** | Read and decode on a worker thread | at run time |
| **Upload** | Meshes and textures to the GPU ([Rendering with wgpu](page:hpy2x2spuf)) | render thread |
| **Use** | Components hold handles, extract looks them up | every frame |
| **Reload** | A changed file is loaded again and swapped in | while running |

## 2\. Handles, not references

Components never hold a `&Texture` or an `Arc<Mesh>` directly: they hold a small `Copy` **handle**, a generational key into the store (the same idea as entities in [Entity Component System](page:vj3mm21ptz)).

```rust
#[derive(Clone, Copy, PartialEq, Eq, Hash)]
pub struct Handle<T> { key: slotmap::DefaultKey, _type: std::marker::PhantomData<fn() -> T> }

pub enum LoadState<T> { Loading, Loaded(T), Failed(String) }

pub struct Assets<T> {
    slots: slotmap::SlotMap<slotmap::DefaultKey, LoadState<T>>,
    by_path: std::collections::HashMap<std::path::PathBuf, Handle<T>>,
}
```

Why:

- **No lifetimes in components**: a handle is just data, so it can sit in the ECS, be copied, be sent across threads.
- **Loading is visible**: `get(handle)` returns `None` while loading; the renderer draws a placeholder (a flat grey ramp, no hatching).
- **Dedup by path**: asking for `"ramps/skin.png"` twice gives the same handle.
- **Hot reload for free**: replacing what is in the slot updates every user at once.

The pattern is in [Rust Patterns for Engines](page:7nta66y9tk).

## 3\. Loading off the main thread

Decoding a PNG or parsing a glTF takes milliseconds, and building edge adjacency for a big mesh more: never do it inside the frame ([Game Loop and Timing](page:kom1zxtzlw)).

```
main thread                         worker threads
  load("hero.glb") ─── request ──►   read file, decode, smooth normals, build edges
  returns Handle (Loading)                       │
  ...frames continue...                           │
  poll channel  ◄────── result ───────────────────┘
  upload to GPU, slot = Loaded
```

- A `std::sync::mpsc` (or crossbeam) channel each way is enough; a thread pool (`rayon`) for many files.
- **GPU upload stays on the thread that owns the device and queue**; workers produce CPU-side data (`Vec<Vertex>`, RGBA bytes, edge lists).

## 4\. Formats

| Content | Format | Crate | Notes |
| --- | --- | --- | --- |
| Models, scenes, animation | glTF 2.0 (`.gltf` / `.glb`) | `gltf` | Right-handed, Y up, metres: matches [Math for Games](page:l0adi79jhz). Custom attributes (`_OUTLINE_NORMAL`) and vertex colours carry NPR data |
| Albedo, paper, brushes | PNG, JPEG | `image` | sRGB textures (`Rgba8UnormSrgb`) |
| Ramps | PNG, a few pixels wide | `image` | See below |
| Hatch maps (TAMs) | PNG per tone and mip level, or KTX2 | `image`, `ktx2` | Hand-built mips: see below |
| Style presets | RON | `ron`, `serde` | [Scripting and Hot Reload](page:sa5xujelgo) |
| Shaders | WGSL | wgpu / naga | Reloadable too |

## 5\. Assets NPR needs

### Ramps

- **Clamp to edge**, never repeat: n·l at 1.0 must not wrap to the shadow colour.
- **No mipmaps** and nearest filtering for hard bands; linear for soft.
- Colour ramps are sRGB; ramps that encode a *value* (a threshold, an ink amount) are linear (`Rgba8Unorm`). Mixing them up shifts every band.

### Tonal art maps

- Each tone and each **mip level** is authored (or generated by a tool that redraws strokes at each size): automatic mipmaps would blur strokes into grey and kill the look at a distance ([Hatching and Painterly Rendering](page:6vwu9pwosr)).
- Tiling: hatch textures must tile seamlessly; repeat addressing, trilinear filtering.
- Pack tones into channels (three tones per RGB texture) to save samples.

### Smoothed outline normals

At import, average the normals of every vertex sharing a position and store the result as an extra attribute. The inverted hull then stays closed at hard edges ([Outlines and Edges](page:sof6p2vevn)). Blender can bake the same into a vertex colour layer if artists want to edit it.

### Edge adjacency

For mesh lines, build a list of unique edges with their two faces (or one, for borders), and mark creases by dihedral angle once. Stored next to the mesh, uploaded as a storage buffer for the edge compute pass.

### Vertex colour channels as style controls

Following *Guilty Gear Xrd*: one channel biases the shadow threshold, one scales outline width, one masks hatching. Artists paint them in Blender; glTF carries them as `COLOR_0`.

## 6\. Hot reload

```rust
// A watcher thread (the `notify` crate) sends changed paths.
for path in changes.try_iter() {
    if let Some(handle) = textures.by_path.get(&path).copied() {
        loader.request(path, handle); // same handle, new contents when it arrives
    }
}
```

- Editors save in several writes: **debounce** (wait \~100 ms after the last event).
- A failed reload keeps the old asset and logs the error: a broken PNG should not crash the viewer.
- Repainting a ramp in Krita and seeing it on the model a moment later is the core art loop ([Scripting and Hot Reload](page:sa5xujelgo)).

---

## 7\. Lifetime and memory

- **Reference counting** of strong handles lets the store free assets nobody uses; weak handles for caches.
- Unload between scenes in bulk rather than one by one.
- Track GPU memory per asset type and per render target in the debug overlay ([Performance and Profiling](page:tmmt1jyud5)).
