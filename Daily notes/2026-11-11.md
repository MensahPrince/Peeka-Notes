## 4\. Suggested classification system

I'd use these categories when building your reusable parameter dictionary.

| Type | Meaning |
| --- | --- |
| CONST | Relatively stable application configuration |
| ENV | Browser/environment information |
| SESSION | Browser/session-associated information |
| INPUT | Supplied by the user or application |
| PAGINATION | Controls data retrieval position |
| CONTEXT | Depends on the page or action |
| DYNAMIC | Changes over time or between requests |
| SIGNING | Request validation/signature values |

The `null` values are intentional placeholders, not missing information.

One important observation: `X-Bogus=1` appears in both captures, but don't assume that this is a valid reusable signature. Likewise, the three other validation values should be investigated independently.

This separation gives you a clean foundation for adding more TikTok endpoints without duplicating every browser parameter.
